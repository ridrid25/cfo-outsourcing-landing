# Спецификация `?start=`-токена для @RidFinance_bot

Лендинг после прохождения экспресс-диагностики формирует ссылку

```
https://t.me/RidFinance_bot?start=<ТОКЕН>
```

Посетитель нажимает кнопку **«Отправить разбор Татьяне»**, открывается бот,
Telegram присылает боту команду `/start <ТОКЕН>`. Задача бота — **раскодировать
токен** по этой спецификации и показать Татьяне человекочитаемый разбор.

> Токен полностью описывает состояние диагностики. Никакого бэкенда у сайта нет —
> вся передача данных идёт через этот параметр.

---

## 1. Формат токена

```
d2_<ниша>_<зоны5>_<ответы3>_<оборот>_<приоритет>
```

* Разделитель полей — символ подчёркивания `_`.
* Первое поле `d2` — **версия формата** (текущая — 2). Если версия не `d2` —
  бот не знает формат, показывает сырой токен и просит уточнить вживую.
* Допустимые символы (ограничение Telegram): `A–Z a–z 0–9 _ -`. Длина ≤ 64.
  Реальная длина токена ~17–20 символов.

| № | Поле | Длина | Что это |
|---|------|-------|---------|
| 0 | `d2` | 2 | версия формата |
| 1 | `<ниша>` | 1 | ниша бизнеса (шаг 1), см. словарь 2.1 |
| 2 | `<зоны5>` | 5 | отмеченные зоны риска, битовая маска `0/1`, см. 2.2 |
| 3 | `<ответы3>` | 3 | ответы на 3 поведенческих вопроса, см. 2.3 |
| 4 | `<оборот>` | 1–2 | месячный оборот, млн ₽ (целое 5–80) |
| 5 | `<приоритет>` | 1 | индекс приоритетной зоны-диагноза `0–4` или `x`, см. 2.4 |

---

## 2. Словари кодов

### 2.1. Ниша (поле 1) — один символ

| Код | Ниша |
|-----|------|
| `s` | Строительство |
| `d` | Дорожная отрасль |
| `p` | Производство |
| `t` | Торговля |
| `u` | Услуги |
| `o` | Другое |
| `x` | Не выбрана |

### 2.2. Зоны риска (поле 2) — маска из 5 символов `0/1`

Порядок фиксированный. Символ на позиции = `1`, если зона отмечена.

| Поз. | Код зоны | Что отметил клиент (формулировка на сайте) |
|------|----------|--------------------------------------------|
| 0 | `deadstock` | Мёртвый склад, зависшие остатки |
| 1 | `receivables` | Растёт дебиторка, платят с задержкой |
| 2 | `discounts` | Скидки «на глаз», без расчёта маржи |
| 3 | `profitability` | Не знаю прибыльность по продуктам |
| 4 | `cashgap` | Случаются кассовые разрывы |

Пример: `01001` → отмечены **дебиторка** (поз.1) и **кассовые разрывы** (поз.4).

### 2.3. Ответы на вопросы (поле 3) — три символа `q1 q2 q3`

Каждый символ: `0` / `1` / `2` — выбранный вариант, либо `-` если вопрос
не отвечен. Чем выше балл, тем острее ситуация.

| Поз. | Вопрос | Усиливает зону | `0` | `1` | `2` |
|------|--------|----------------|-----|-----|-----|
| q1 | Знаете, сколько денег будет на счетах через месяц? | `cashgap` | Вижу прогноз в любой момент | Прикидываю раз в месяц | Вспоминаю, когда прижмёт |
| q2 | Назовёте самый прибыльный продукт по цифрам за 5 сек? | `profitability` | Да, знаю точную маржу | Примерно чувствую | Не уверен |
| q3 | Скидки клиентам — как решаете? | `discounts` | По расчёту маржи | По ситуации | Как договоримся |

Пример: `2--` → на q1 ответ «Вспоминаю, когда прижмёт» (балл 2), q2 и q3 не отвечены.

### 2.4. Приоритетный диагноз (поле 5) — индекс зоны

Сайт уже выбрал **главную зону** (по остроте, тай-брейк — сумма потерь) и
кладёт в токен её индекс из таблицы 2.2 (`0–4`). Боту **не нужно** повторять
эту логику — просто возьмите зону по индексу.

| Индекс | Зона | Заголовок диагноза (для сообщения) |
|--------|------|------------------------------------|
| `0` | deadstock | Склад, который не двигается |
| `1` | receivables | Дебиторка: деньги есть, но не у вас |
| `2` | discounts | Скидки на ощущениях съедают маржу |
| `3` | profitability | Непонятно, что кормит, а что тянет вниз |
| `4` | cashgap | Деньги во времени — самая опасная зона |
| `x` | — | Острых зон не выявлено |

## 3. Пример: токен → расшифровка

Токен:

```
d2_s_01001_2--_30_1
```

Разбор по полям:

| Поле | Значение | Расшифровка |
|------|----------|-------------|
| версия | `d2` | формат 2 |
| ниша | `s` | Строительство |
| зоны | `01001` | Дебиторка + Кассовые разрывы |
| ответы | `2--` | q1 = «Вспоминаю, когда прижмёт»; q2, q3 — без ответа |
| оборот | `30` | 30 млн ₽/мес |
| приоритет | `1` | Дебиторка: деньги есть, но не у вас |

## 4. Шаблон сообщения боту → Татьяне

После расшифровки бот показывает Татьяне примерно такое сообщение:

```
🧭 Новый разбор с сайта

Ниша: Строительство
Оборот: ~30 млн ₽/мес

Отмеченные зоны риска:
• Дебиторка, платят с задержкой
• Кассовые разрывы

Ответы:
• Деньги на счетах через месяц: «Вспоминаю, когда прижмёт»
• Прибыльный продукт по цифрам: — (не ответили)
• Скидки клиентам: — (не ответили)

Приоритетный диагноз: Дебиторка — деньги есть, но не у вас.

(токен: d2_s_01001_2--_30_1)
```

Поля «не выбрана / не отвечено / острых зон нет» можно либо опускать, либо
показывать как «—», на усмотрение бота.

## 5. Готовая функция расшифровки (JavaScript)

```js
const NICHE = { s:'Строительство', d:'Дорожная отрасль', p:'Производство',
                t:'Торговля', u:'Услуги', o:'Другое', x:'Не выбрана' };

const ZONES = [
  { key:'deadstock',     chip:'Мёртвый склад, зависшие остатки',     diag:'Склад, который не двигается' },
  { key:'receivables',   chip:'Дебиторка, платят с задержкой',       diag:'Дебиторка: деньги есть, но не у вас' },
  { key:'discounts',     chip:'Скидки «на глаз», без расчёта маржи',  diag:'Скидки на ощущениях съедают маржу' },
  { key:'profitability', chip:'Не знаю прибыльность по продуктам',    diag:'Непонятно, что кормит, а что тянет вниз' },
  { key:'cashgap',       chip:'Кассовые разрывы',                     diag:'Деньги во времени — самая опасная зона' },
];

const QUESTIONS = [
  { q:'Деньги на счетах через месяц', opts:['Вижу прогноз в любой момент','Прикидываю раз в месяц','Вспоминаю, когда прижмёт'] },
  { q:'Прибыльный продукт по цифрам', opts:['Знаю точную маржу','Примерно чувствую','Не уверен'] },
  { q:'Скидки клиентам',              opts:['По расчёту маржи','По ситуации','Как договоримся'] },
];

// Возвращает структуру разбора либо null, если токен не распознан.
function decodeToken(token) {
  const p = String(token || '').split('_');
  if (p[0] !== 'd2' || p.length !== 6) return null;       // чужой/старый формат
  const [, niche, mask, answers, turnover, priority] = p;

  if (!/^[01]{5}$/.test(mask)) return null;

  const zones = ZONES.filter((_, i) => mask[i] === '1').map(z => z.chip);

  const answersText = [...answers].map((a, i) => {
    if (a === '-' || QUESTIONS[i] == null) return { q: QUESTIONS[i]?.q, answer: null };
    return { q: QUESTIONS[i].q, answer: QUESTIONS[i].opts[Number(a)] ?? null };
  });

  const diagnosis = /^[0-4]$/.test(priority) ? ZONES[Number(priority)].diag : null;

  return {
    niche: NICHE[niche] || NICHE.x,
    turnover: Number(turnover),          // млн ₽/мес
    zones,                               // массив отмеченных формулировок
    answers: answersText,                // [{q, answer|null}]
    diagnosis,                           // строка диагноза или null (острых зон нет)
    raw: token,
  };
}

// Сборка текста сообщения для Татьяны
function renderForTatiana(token) {
  const d = decodeToken(token);
  if (!d) return `Не удалось разобрать токен: ${token}`;
  const L = ['🧭 Новый разбор с сайта', '',
    `Ниша: ${d.niche}`,
    `Оборот: ~${d.turnover} млн ₽/мес`, '',
    'Отмеченные зоны риска:',
    ...(d.zones.length ? d.zones.map(z => `• ${z}`) : ['• не отмечены']), '',
    'Ответы:',
    ...d.answers.map(a => `• ${a.q}: ${a.answer ?? '—'}`), '',
    `Приоритетный диагноз: ${d.diagnosis ?? 'острых зон не выявлено'}`, '',
    `(токен: ${d.raw})`];
  return L.join('\n');
}
```

Псевдокод для любого другого языка повторяет ту же логику: `split('_')` →
проверить версию `d2` и длину 6 → достать поля по словарям выше → собрать текст.

---

## 6. Поведение до доработки бота

Пока бот не умеет разбирать токен, ссылка `?start=` всё равно открывает
@RidFinance_bot, и клиент попадает в диалог. Просто разбор **не развернётся
автоматически** — Татьяна увидит обычный `/start`. Это ожидаемо: воронка не
теряется, но структурированный разбор появится только после доработки бота
по этой спецификации.
